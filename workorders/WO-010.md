## Scope  *(to be finalised at kick-off)*

- **Implements features:** #Content's library lines that new puzzles touch — #PuzzleShapes (REQ-038), #PuzzleArt (REQ-039 A1), #PuzzleOrder (REQ-040), #PuzzleWarmups (REQ-041) as far as a new puzzle changes the order, #PuzzleVolume (REQ-042 A2..A3; A1 — "at least 20 reviewed" — stays WO-009's with the owner's review marks), REQ-007 (every listed puzzle solvable and well-formed). The kick-off settles the exact IDs.
- **Governed interfaces touched:** `IPuzzleLibrary` + the `tangram-puzzle/1` format (**consumed**, locked — puzzles are added in the existing format; a format change would leave the pipeline). None changed.
- **Work per accepted figure** (owner rules 6–7, G-05):
  1. convert it to a `Tangrams/<id>.json` file in the `polygon` form — scale small-triangle legs 1 → the 4 × 4-square units of `Spec/03`, map the y direction and the README's parallelogram-mirror convention onto TYPE-003, snap hand-drawn points to the ℚ(√2) lattice (`design-inputs.md` §2 item 16);
  2. `kind`, `rating` (REQ-040 order), `en` title (Contract) and `fi` title (reference, `review-notes.md`);
  3. a picture (REQ-039: inside the outline, 3–8 colours) drawn for this project;
  4. `provenance` naming the collection, the source figure id and its licence; `reviewedByHuman: false` (the AI never sets it true);
  5. `python tools/validate_puzzles.py Tangrams` and `python tools/render_puzzle.py Tangrams Tangrams/previews` green, the preview sheet looked at, and the Kotlin load check (`:content:testDebugUnitTest`, every bundled file) green;
  6. every kit that iterates the bundled puzzles stays green on its channels (e.g. "solve now" and REQ-002.A1 over every puzzle).
- **Out of scope:** the owner's review marks and the `mark` command (WO-009, DI-8); a shipping-licence notice beyond `ASSET-LICENCES.md` (WO-007 / WO-009, `chg-draft-licence-notice-and-assets.md`); difficulty levels or auto-flip (owner rule 12; `design-inputs.md` §2 item 14); copying any code or data from `sources/twpride-tangram/` (no licence); `kilogram-1013` figures (research-only licence) and the `richter-anchor-179` trace (unlicensed; no solutions) as shipped data.

## Constraints & notes

- **Licence (checkpoint item 1, answered 2026-10-18):** `convex-13` (CC0) and `android-tangram-131` (GPL-3.0 — the app's own licence, `LICENSE`) ship as figures; each shipped figure's collection, source id and licence go into its `provenance` and into `ASSET-LICENCES.md` (credit: Typraeurion/Android-Tangram, GPL-3.0; László Németh, CC0). Pictures stay drawn for this project. `nevit-dilmen-203`, `kilogram-1013`, `richter-anchor-179` and `sources/twpride-tangram` are **not** used. **P3 first step:** amend `architecture.md` G-16 through the G2 route (governance row 4, `unlocked` hatch, re-freeze; the owner's answer and `chg-draft-licence-notice-and-assets.md` as amended 2026-10-18 as the source) and, in the same touch, add the O-06 exception line for the DEV aid's strings (WO-005 code review N2).
- **Count (checkpoint item 2, answered 2026-10-18):** no launch cap — every passing, non-duplicate figure is imported now. The first-release selection is decided before WO-009 (REQ-042 "at least 20"); each shipped puzzle still needs the owner's review mark (REQ-039, `reviewedByHuman`), so a large library costs review time later, not now.
- **Risks the plan must measure, not assume** (13 → ~157 puzzles):
  - **Start-up:** `:app` parses and validity-checks the whole bundle off the main thread behind the blank loading paper (WO-004); 13 puzzles took 0.7–2.3 s cold. Measure on both images with the full bundle; if the wait grows past a few seconds, that is a design decision for the plan (e.g. checking validity at build time — a `decisions.md` row, not a silent change).
  - **The grid overview** composes every cell (WO-004 decision "all composed, not lazy"); with ~157 cells, measure its open time and scrolling on the floor image.
  - **Kit runtime:** tests that iterate every bundled puzzle (the REQ-011.A1 seam check, REQ-002.A1 and the DEV aid's "solve now" over every puzzle, the content load kit) grow about 12×; the plan names their channel times and whether any needs a sample instead of the whole bundle (a test change cites its REQ's quantifier — "every" stays "every" unless a CHG says otherwise).
  - **Pictures:** about 144 pictures to draw (REQ-039: inside the outline, 3–8 colours) — the plan splits the work into batches that can fan out, each validated and rendered.
  - **Names:** the Android-Tangram names are English ("Cup", "Chevron"…) and some are generic ("Square"); the convex ones are numbered — titles need choosing (en Contract, fi reference in `review-notes.md`).
- **Overlap with existing puzzles:** skip a figure whose outline equals a shipped puzzle's (e.g. the convex square or rectangle against "Gift box" / "Chocolate bar").
- **Verification channels (G3, at kick-off):** the Python tool channel (validator + renderer + preview sheet); JVM (`:content`, `:play` — the two-run line); the device sets that iterate the bundle, on the dev and floor images; V-01.
- **Design inputs:** DI-10 (figures — `generated`, numbers are not an oracle), DI-5 (format, schema, tools). `design-inputs.md` §2 items 14–16 first.
