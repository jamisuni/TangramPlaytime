## Goal

Count play time the way the owner asked for it ("keep track of per puzzle
time used to solve plus total ACTIVE time", SRC-002): every puzzle counts its
own active seconds and keeps its best solve, the game counts today's and the
all-time active play time, and an optional timer shows the running puzzle
time on the board (off by default). The first task moves the code to the
owner's new floor, Android 12 (`minSdk 31`). Runs before WO-007 #Settings
(`decisions.md` 2026-10-20 "WO-008 #PlayTime runs before WO-007 #Settings"):
the settings screen shows these times and pauses the puzzle time, so it is
built on real counting.

2. **TYPE-005 as code.** When a second counts (visible on screen **and** the last touch at most 60 s ago), what "visible" is on Android (which lifecycle state), whole seconds and how partial seconds are kept or dropped, the injected `Clock` (G-14, ADR-006), and what happens across a process death.
3. **Play time vs puzzle time.** Today's and all-time play time count every active second whatever is on screen; a puzzle's own time counts only while that puzzle is In progress, shown, and no overlay is open (`design-inputs.md` §2 "Time counting"; TYPE-006 rule 4; REQ-030 rule 1). Name each screen and overlay the game has today (board, solved view, grid overview, the DEV aid's prompt) and say what counts on each.

5. **Best time** (REQ-030 rules 2–4): set when a puzzle is solved, the shorter kept; Restart and Retry reset the running time, never the best; an aid solve sets none (must-do 1); what the solved view shows (REQ-026, built in WO-004 with "–" for none).
6. **When times are written** through `:play`'s one FIFO writer (`Persistence`, ADR-003) and how much counting a process death may lose — no REQ quantifies it; name the bound and its reason (DI-1's every-5-seconds cadence is not a rule, `design-inputs.md` §2 item 11).
7. **The timer on the board** (REQ-031): its place (the board's top-right corner), what it shows and in which format (REQ-029's m:ss / h-and-min rule is for play time — say whether the timer follows it), its digits under every device language (WO-010's counter lesson: `Locale.ROOT`), when it is hidden (default off, `Settings.timerShown`), and how the kit turns it on without the settings switch (WO-007).
8. **The TYPE-006 transitions** (must-do 3): move or stay, with the reason.
9. **The kit's clock.** Time is injected, never slept (`task-decomposition.md`; `platform-notes/android.md` "Time-driven tests set the injected clock …"); which lines are proven on the JVM and which need a device.
10. **Seams and tokens.** One seam table row per seam, each naming its task; the tokens' code homes per `build-map.md` (a screen-half token outside `kernel/` needs a build-map row, a notify-tier delta).
